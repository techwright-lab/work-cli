# macOS retained inspection: safe Rust platform boundary

## Result for #23 and the #20 handoff

**A bounded hard-link acquisition seam is concretely implementable through the already locked safe `rustix::fs::linkat` API on macOS. A complete accepted macOS collector is not yet available from the locked dependencies.** The missing safe bindings are sharply identifiable: anchored native attribute acquisition, explicitly refill-bounded directory enumeration, and sufficiently complete private-stage access/mount observations. Public unprivileged Darwin interfaces exist for these jobs. Their absence from rustix is not their absence from macOS, nor evidence that Work must contain unsafe code. [R1–R5, A1–A6]

The useful design is **held-parent walk → one-entry hard-link capture → nofollow classification and source/stage binding → protected-stage readable open → bounded read and final validation**. This avoids the recursive-directory clone acquisition failure and preserves the original inode after successful linking. It does **not** make that inode immutable. Do not replace source consistency checks with a stopped-writer declaration, ignore all ctime changes, or subtract arbitrary links from `st_nlink`. [P1–P4]

**Remaining acceptance blockers, not a request for indefinite research:**

1. Choose/approve a safe binding delivery route for the specific missing interfaces below; no candidate dependency is selected here. Existing Rust lints need not be relaxed to use a separately audited library with a safe public interface.
2. Demonstrate the stage-protection, bounded-enumeration/parser, and own-link accounting protocol at the stated barriers. Hard-link permission in #26 is conditional, not acceptance of those protocols.
3. Discharge the precise mount-boundary gap: observed topology plus held-parent identity checking can establish a qualified stable-topology route, but is not an atomic `NO_XDEV` traversal prohibition. If the approved boundary demands prevention of even transient foreign-mount traversal before validation, the interfaces screened here do not establish it. That remains a bounded blocker, not permission to downgrade the contract.

This is source/design analysis only. No native probe, build, toolchain installation, mount, reboot, real-state/credential/config inspection, local Git write, checkout/worktree operation, production implementation, PR, merge, issue closure, or map update was performed. Source downloads and report preparation were confined to the assigned scratch cwd. The baseline was read only.

### Library unsafe versus Work unsafe

Rust's `forbid(unsafe_code)` does not transitively ban unsafe implementation inside dependencies. Rustix already encapsulates FFI and pointer operations, including `fdopendir`/`readdir`, behind safe APIs. A call to its safe `linkat` does not require an unsafe block in Work. Conversely, raw `libc::getattrlistat`, raw `getfsstat`, or `acl_*` calls would require unsafe at the call site; importing `libc` alone does not supply a safe wrapper. A new in-tree crate that evades the workspace lint is **not** an authorized workaround. [W1, R2, R4]

**Concrete safe binding delivery choices for the operator, not selected dependencies:** extend/upstream the existing maintained safe syscall library and adopt an approved version, or approve a separately audited Darwin binding dependency with a narrowly safe interface. That interface must own/borrow FDs correctly, validate component arguments and sizes, initialize output storage, preserve errno/returned masks/counts, and not perform hidden unbounded retries. Safe slice-based decoding can remain in forbidden-unsafe Work code. No need to relax Work's lint has been established. This report does not authorize either delivery choice.

### Candidate maintained libraries and narrower alternatives

- **rustix 1.1.5** (`287214b889865d8e1406a0ee71cc409b6f6191c8`): the existing dependency supplies the hard-link/FD/no-follow/statfs core. Its `RawDir`, `openat2`, Linux `ResolveFlags` and `statx` are not macOS substitutes. It does not expose the requested generic attribute/ACL/mount-table functions. This is a **locked-version export finding**, not a claim about future rustix or Darwin. [R1–R5]
- **nix 0.31.3** (`b5933ca178802b558a667514f717a86b3a1cedcc`; published 2026-05-11, MSRV 1.69): maintained general safe syscall alternative. `unistd::linkat`, `sys::stat::fstatat`, `sys::statfs::fstatfs`, and `dir::Dir` exist with relevant features. Its directory abstraction also uses libc streams; no generic Darwin attribute/token, FD ACL, or raw bounded `getfsstat` interface was found in this finite screen. Adding it does not solve the identified gaps and duplicates available rustix functionality. [R6]
- **exacl 0.13.0** (`fa36df1745a41e50ab0730546c04d86a8503e46b`; published 2026-05-05, MSRV 1.85): maintained safe macOS ACL reader/writer. It returns allow/deny entries with permissions/inheritance flags and resolves UUID principals via membership functions. - **getattrlistbulk 0.1.0** (`072985b4c2b06656e61556cd6ceea83362996130`; published 2026-01-18, MSRV 1.70): a safe-public-API specialist crate, but not a demonstrated maintained/drop-in safety solution (the archive's repository/commit source URLs returned 404 during validation; use the exact published crate source below). Its public constructors take a pathname, not a caller-held parent/FD; its open omits nofollow and CLOEXEC. More decisively, `refill_buffer` ignores the syscall's positive entry count and `find_valid_bytes` scans the entire reusable buffer by embedded lengths. A shorter later batch can expose stale records beyond the actual returned count. It also recursively retries EINTR internally without a caller budget. These are source-level rejection reasons, not a newly executed exploit or a blanket assertion that `getattrlistbulk` is unsafe as an OS interface. [R9]
- **whichdisk 0.7.0** (`4f60daff70d62df1cbf581c391dcf71a2c057f72`; published 2026-10-01, MSRV 1.85): safe high-level storage observation candidate. This is useful evidence that safe encapsulation is possible. Public `list`/`resolve` return high-level mounts/path locations, however, not the caller's raw held-FD/real-ID/token interface or caller-chosen budgets; the public listing is explicitly a real/non-virtual-volume listing, not an unfiltered topology census. Treat it as a bounded topology-information candidate requiring its own dependency/semantic audit, **not** a proof of containment or a ready-made implementation of this seam. [R8]

The finite screen does not prove no suitable safe library can exist. It establishes exactly what the current lock provides and why the screened additions do not complete the collector unchanged.

## 3. Fresh bounded directory enumeration and parsing

### Existing stream route: useful, but qualified

The rustix libc backend's `Dir::read_from` opens `.` to avoid shared offsets; `Dir::new` consumes an FD. Reopening an explicit fresh directory FD and verifying its identity before handing it to `Dir` is a plausible **qualified** route. But counting calls to `Dir::read` does not count all native work:

- Apple `fdopendir` uses `DTF_HIDEW | DTF_NODUP`; on `MNT_UNION` the inspected Libc calls `_filldir`, reading/allocating the whole directory before iteration. This is an operation-specific reason to refuse that enumeration mechanism on observed union stacks, **not a blanket storage ban**. Ordinary non-union enumeration uses initial/large fixed buffers rather than directory-sized growth. [A6]
- `readdir` may internally skip dead entries/whiteouts and refill repeatedly before returning a name. Rustix does not expose those refill counts. Native libc performs record parsing; certain invalid-record paths in the inspected source return NULL without explicitly setting errno. Rustix distinguishes NULL+errno from EOF, but cannot recover a parser failure that libc reports as EOF. A strict fail-closed malformed-buffer contract is not established merely by wrapping `Dir` in an entry counter. [A6, R4]

Thus do not label `Dir` an exact replacement for the baseline's caller-buffer `RawDir`. If its qualified boundedness/error semantics suffice, acceptance must explicitly be based on those native semantics and evidence, not on name-count budgets alone.

### Concrete bounded-buffer route

The more controllable native seam is **one fresh FD per census plus `getattrlistbulk` into fixed/capped caller storage**. This is not a new dependency choice. The required safe wrapper/decoder contract is finite: [A3, A4]

1. Open `.` afresh relative to a held, revalidated directory with directory/no-follow/CLOEXEC restrictions; compare FD identity and mount to the held directory. Do not dup a used cursor or mix `readdir` and bulk calls on one FD (the manual calls their mixing undefined).
2. Request at least `ATTR_CMN_NAME | ATTR_CMN_RETURNED_ATTRS`; request `ATTR_CMN_ERROR`, type/file ID, `ATTR_DIR_MOUNTSTATUS`, and flags as needed. Charge the fixed buffer, each native refill, each returned record/name byte, retained manifest entries, and retry before doing work. No unbounded internal EINTR loop or resize-to-fit. Zero entries is EOF for that FD, **not** proof no later names exist; a new census needs a fresh cursor.
3. A positive return is **record count**, not bytes. Decode exactly that many length-prefixed groups. Require each group start/length and each field/reference to lie within the caller buffer and its own group; validate count consistency and forward progress. Never scan old buffer contents for a guessed end marker. Bulk group starts are documented 8-byte aligned; individual attributes follow getattrlist's 4-byte alignment, including 64-bit integers.
4. Use checked integer arithmetic and byte copies/`from_ne_bytes`, not unaligned typed casts. Check leading lengths, returned masks, requested packing mode, per-entry error, attrreference's **signed offset relative to the reference**, length, terminator and embedded NUL; reject slash, empty, `.` and `..` as child components. Treat names as filesystem bytes, not lossily converted text. Any unsupported encoding observation must cause explicit incomplete inspection, not skipped entries.
5. With `FSOPT_PACK_INVAL_ATTRS`, invalid fields occupy slots but their defaults are not evidence. Require each mandatory returned bit. An `ATTR_CMN_ERROR`, malformed/truncated record, over-budget result, vanished entry or incomplete census is a hold, never a clean/empty tree.
6. Ignore neither native mountpoint status nor `SF_FIRMLINK`. Bulk metadata for a mounted directory is from the **covered underlying mountpoint**, not the mounted root. Bulk metadata for a firmlink is from the firmlink, not its target. Bind separately to the actual object opened/observed via the child name. A disagreement is not solved by trusting `d_type`/bulk type. [A3]

The public historical `getdirentries` manual is **not** sufficient justification for calling a modern 64-bit raw syscall: it explicitly deprecates that function and says it does not work with 64-bit inodes without the legacy feature selection. Libc's `__getdirentries64` implementation is real, but copying its private spelling/ABI into Work is not an already-approved public binding. Bulk enumeration avoids relying on that inference. A caller buffer bounds transfers and decoding, **not a hard wall-clock limit on a single filesystem syscall**; cancellation/timeouts do not retroactively bound in-kernel work or prove the mutation outcome. [A6, A9]

## 4. Filesystem identity, held-parent walking, and the exact no-XDEV gap

### What one-component walking does establish

Validate every component as one nonempty name without slash/NUL, excluding `.`/`..`; use it only relative to a retained parent FD. Acquire directories with `O_DIRECTORY|O_NOFOLLOW`, compare name metadata to the returned FD, and retain the chain as `(parent FD, exact name bytes, child FD, binding identity)`. A symlink swapped in as that component is rejected, including an intermediate symlink because **each component is individually the final component of a restricted lookup**. Absolute paths and `..` escapes never reach the syscall. This is a viable strategy on versions without the newer beneath flags; it does not require Linux `openat2`. [R2, A2]

After acquisition, revalidate each parent-name-to-child binding from the registered root/authorized ancestor chain before capture/read and at final acceptance. A held directory FD remains usable if the directory moves outside the checkout; it is not proof of current root membership. Compare relevant owner/access/type and actual identity for outside traversal bindings without invalidating merely because unrelated siblings changed. For directories **inside the census**, preserve full content/metadata observations and re-enumerate; route equality is not a complete-census check. The baseline makes this distinction too. [W2, P4]

Newer `O_RESOLVE_BENEATH`, `AT_RESOLVE_BENEATH`, and `FSOPT_RESOLVE_BENEATH` are visible in the newer XNU snapshot, but not in the compared older headers. `O_NOFOLLOW_ANY` and `AT_SYMLINK_NOFOLLOW_ANY` already appear in the older snapshot. Do not assume a newer flag's runtime support on macOS 15/26 or an exported rustix constant because a newer Apple header has it. Component walking avoids depending on those newer flags for lexical/symlink containment, **not for all mount semantics**. [A2, A8, R3]

### What to observe about mounts

Keep separate:

- **object key:** real mounted-volume identity plus file ID/type (retained FD or capture prevents reuse after retention);
- **current mounted instance/topology evidence:** FD `fstatfs`, `getfsstat` records, directory mountpoint status/firmlink observations and held-parent bindings;
- **persistent volume identity:** a supported volume UUID/capabilities, if the lifecycle operation requires persistence across mount/reboot. UUID equality is not a current-mount traversal proof.

`st_dev`/logical fsid alone may be insufficient on volume groups. The attribute manual explicitly says `FSOPT_RETURN_REALDEV` makes `ATTR_CMN_DEVID/FSID` return the physical volume's values instead of a possible common logical value. Alternatively request `ATTR_CMNEXT_REALDEVID` and `ATTR_CMNEXT_REALFSID` with extended-common interpretation. The inspected implementation packs the mounted vnode's mount fsid on its direct-vnode route; require returned masks and bind the answer to the FD/name identity being checked. Do not infer real identity from a path prefix, APFS label, equal UUIDs, or a reconstructed no-firmlink pathname. [A4]

Use a capped caller-owned `getfsstat(MNT_NOWAIT)` census (or an approved equivalent) as corroborating observed topology; refuse truncation/full-buffer ambiguity and changes relevant to the route. A count-then-fill sequence is not atomic. Returned mount path strings have fixed sizes and are not authoritative root-membership proofs, especially for aliases/case variants; compare real identities and actual held routes. Do not refresh unrelated network mounts just to qualify one local operation. [A5, P1]

### Exact equivalence gap

A prechecked non-mountpoint can be mounted over before `openat`; an opened directory can already be on a foreign mount before `fstatfs` rejects it. Same real-fsid equality does not prove no mount transition occurred along the route, especially aliases/stacked views. A mount can appear and disappear between two censuses. `O_NOFOLLOW` prohibits symlink following, not mount following; beneath confines a hierarchy relative to a starting FD, not a no-mount-crossing rule. No public atomic `NO_XDEV`-equivalent flag was established in this screen. [A2–A5]

For file acquisition, **successful `linkat` is stronger than a device-number guess**: the inspected kernel compares `vnode_mount(source)` with `vnode_mount(destination_parent)` before `VNOP_LINK`, returning EXDEV if different. It establishes same mounted filesystem for that link, but does not certify that no earlier directory lookup crossed a forbidden mount or authenticate root membership. It does not let a stage on one mount collect from a separate allowed location/volume. [A1]

Consequently:

- A qualified stable observed topology, single-component walking and revalidation can be a coherent containment design under the cooperative boundary. Test actual relevant transitions and refuse uncertain ones.
- It cannot be described as an atomic ban on every transient crossing. If foreign directory acquisition itself is prohibited, post-open mount checks cannot undo it. That precise requirement remains blocked until a prevention mechanism/equivalence argument is accepted; no blanket ban on every external volume, every firmlink on the host, cloud directories, or harmless read-only commands follows.
- #22 allows APFS as initial qualification scope, case variants only after qualification, and operation-specific refusal of unproven mutation behavior. Neither APFS type alone nor refusing every mount is the missing proof. [P1]

## 5. Protected-stage handoff and hard-link consistency

### Concrete ownership and pre-data-open protocol

The following defines the implementation seam and its invariants, **not accepted production code or automatic cleanup authority**. [P2, P3, A1, A7]

1. **Reserve before mutation.** Retain/validate a stage parent on the source's actual mounted filesystem, outside the source census. Bound stage objects, manifest/log bytes, FDs, names, syscalls, inspection bytes/metadata and retries. Hard-linking retains existing allocation if the user unlinks the source; a one-entry capture is not necessarily one block of resource cost. Keep charge/evidence on interruption. Disclose preview's temporary nlink/ctime changes.
2. **Establish a protected new active stage.** Create a fresh directory relative to a protected held parent, with owner-only requested mode, then validate the actual FD/name identity, ownership, effective permissions and inherited ACL. A requested 0700 mode is not proof against extended ACL grants. Validate relevant parent deletion/rename rights and stage traversal/add/delete/security-changing access so unrelated principals cannot replace its entries. Exclude concurrent Work capture/cleanup actors by the active-session protocol/lock; do not rely on a random-looking name.
3. **Record a capture intent**, with active session, source chain/name/object observation, stage mount/directory identity, fresh destination name, reservation and expected own-link count. No overwrite. Then `rustix::fs::linkat(..., AtFlags::empty())` links at most one entry; no recursive directory-copy fallback. On failure or ambiguous completion, preserve accounting and state. A crash between syscall success and result recording is an unknown outcome, not authority to adopt the entry from its name.
4. **Classify the new stage name without following it** using `statat`. Reject FIFO, device, socket, symlink or directory before readable payload open. The kernel normally rejects directory hardlinks, but the inspected source has an explicit `MNTK_DIR_HARDLINKS` exception: do not generalize the APFS probe into an absolute all-filesystem prohibition. Even such a link is not recursive capture; it is still an unsupported type/side-effect hold. No chmod/chown/ACL clearing of a linked payload: that would edit the original inode.
5. **Bind before any readable payload open.** Stage/source observations must refer to the same retained object and expected source route. Require the pre-observed object binding, still-current source name and entire ancestor route, same actual mount, regular type, allowed original user-link status, exact active owned-entry record, budget, relevant metadata, valid required data generation and any accepted auxiliary token. Retain the capture link while checking; once linked it pins that inode, avoiding post-retention inode reuse. Initial precheck alone did not pin it; do not use inode/timestamp equality as a universal pre-link anti-ABA proof.
6. **Private-stage name → readable FD.** Only after the barrier, open the stage's single validated name with `RDONLY|NOFOLLOW|CLOEXEC` (NONBLOCK may be defensive, never the type filter); immediately `fstat`/check real mount and expected inode/type before reading. The *reason this open cannot reach a replacement special file* is that the protected directory's entry cannot be replaced by unrelated principals, no other active Work actor mutates it, and malicious same-UID interference is excluded. The object type of a retained regular inode does not transform into FIFO. The reason is **not** a post-open type check or O_NOFOLLOW. If stage exclusivity is not established, stop before this open; safe Rust types do not fix that OS race.
7. **Bounded read and revalidation.** Read through that FD only, enforcing bytes/growth/EOF limits and before/after data/metadata observations. Check live source name, held ancestors, mount evidence and complete fresh census again after read and before destructive acceptance. Concurrent writes through any source/user FD still mutate this same inode. Late changes invalidate inspection; they cannot promise zero bytes already read for a change that happened after the pre-read barrier. Stopped-writer confirmation remains separately mandatory.
8. **Normal active cleanup only.** Remove only the exact capture entries proven owned by this active validated protocol, through the held protected stage FD; revalidate entry/object/stage before unlink. Removal changes source ctime again. Unknown names, receipts, outcomes or leftovers hold with evidence/charge. Nothing in this report approves generic age/name-based orphan cleanup or recovery adoption, permission repair, checkout removal or charge release.

### Why stage privacy requires more than `access(W_OK)`

`accessat(..., EACCESS)` and `ATTR_CMN_USERACCESS` answer whether **Work's current credentials** have access. They do not establish absence of write/search/delete/security rights for other users or groups. Darwin's ordered extended ACLs, inheritance, parent delete-child rights, ownership and ignored-ownership mount behavior matter. An inherited benign read-attributes ACE or an effective deny is not automatically disqualifying; #22 explicitly rejected a blanket ACL ban. Unknown relevant access must refuse this operation without stripping the ACL. [P1, A4, A7]

Two public acquisition routes are concrete: `fgetattrlist(stage_dirfd, ATTR_CMN_EXTENDED_SECURITY|…, bounded_buffer, …)` with checked raw `kauth_filesec` decoding, or `acl_get_fd_np(stage_dirfd, ACL_TYPE_EXTENDED)` and bounded ACL iteration/free via a safe library. The former also fits the missing attribute-binding seam; the latter needs an FD wrapper not provided by the screened exacl public API. Preserve raw principal UUIDs, ACE order and unknown bits for classification; don't convert unresolved identity into “owner” or assume membership lookups cannot fail. A conservative access proof may accept ACLs whose relevant grants are proven harmless without implementing arbitrary network-directory membership evaluation. This report does not choose a new ACL-admission policy. [A7, R7]

Protecting the stage **namespace** does not make the hard-linked payload private from principals who can already reach the source, nor stop open writable FDs/mappings. Conversely, a source metadata chmod cannot on its own replace the entry inside a genuinely inaccessible stage directory. Keep namespace exclusion and mutable-object consistency as separate arguments.

### Ordinary-concurrency and user-hardlink pitfalls

| Schedule/pitfall | Required response / remaining limit |
| --- | --- |
| Regular A replaced by FIFO/symlink before linking | Link, if supported, captures that one object without a payload-readable open; classify and refuse before opening. No recursive descent and no follow-source-symlink fallback. |
| Regular A replaced by directory | No clone recursion. Normally link fails; kernel's directory-link exception means classify successful result too. Do not claim the experiment established every filesystem's refusal. |
| A moved/replaced after successful link | Private link still retains A, but current live source/ancestor binding fails; refuse before readable open in that schedule. Opening retained A merely because it is safe to open is not permission to accept a changed census. |
| Ordinary writer changes A through existing FD or mmap | Stage sees the same mutable inode. Valid generation/metadata comparisons and post-read checks are mandatory. Private stage does not exclude these writes. |
| Pre-existing user hardlink | Require the baseline supported-link condition **before adding Work's link**; do not normalize pre-existing `nlink > 1` into acceptance. Unknown old capture links also hold. |
| User adds/removes links concurrently | With one established original and one proven active Work link, expected current nlink is exactly 2; user-link additions normally make it 3 and hold. If original name vanishes while another user link appears, nlink may still be 2: live source binding is independently required. Counts prove totals, not ownership/provenance. |
| Source/path ABA during acquisition | The created link retains whichever inode `linkat` actually resolved. Compare it to source observations before reading; do not mistake syscall success for an atomic expected-ID receipt. A restored source name does not authenticate a different captured inode. Once A is retained, inode reuse cannot substitute it while the capture link lives. |
| Own-link count/ctime mutation | #26 allows that specific effect, **not ignoring ctime globally**. Preserve S0 separately; compare every non-exempt field and complete metadata evidence; establish a strict post-link baseline for later comparisons. Link creation/removal must be explicit transitions, not rewritten historical identities. |
| Concurrent metadata edit masked by own ctime change | There is no atomic pre/post metadata receipt from `linkat`. Endpoint equality of ACL/xattrs plus an expected ctime change cannot prove no intermediate change. Data generation is not a metadata generation. **This acquisition-window attribution gap remains evidence to discharge**, not a timestamp heuristic or permission to accept arbitrary metadata churn. No proof of detecting every restored intermediate state is claimed for either platform. |
| Crash after linking but before durable result, or cleanup error | Preserve unknown outcome and resources; old receipt/filename/nlink arithmetic is insufficient to adopt/remove. #26 requires ownership/outcome recovery evidence and any necessary explicit operator disposition. |

A safe implementation must not compare a later scan against old pre-link ctime as though unchanged, but must equally not discard its only signal of external changes. If the required ordinary-concurrency contract cannot be demonstrated across the self-mutating acquisition window, the result is **that bounded protocol blocker**, not a reason to silently waive consistency or switch back to unbounded clone capture.

## 6. Generation, clone and link tokens: precise roles

The attribute safe binding should return a typed observation containing actual returned masks plus values; unsupported/default fields are not present evidence. [A4]

- **`ATTR_CMN_GEN_COUNT`**: documented nonzero monotonically increasing 32-bit count of **data** modifications for the *same* filesystem object; unchanged means identical data by the documented comparison. Zero is invalid, including while mmap'ed. Require `FSOPT_ATTR_CMN_EXTENDED` and valid returned bit/value. `stat.st_gen` is not this data-generation API. Do not assert unique timestamps, metadata-change coverage, unbounded wrap immunity, or that endpoint nonzero observations alone prove no intervening invalid mapping interval. Experiment 5's initial mapped-file refusal is not the complete interval proof.
- **`ATTR_CMNEXT_CLONEID`**: identifies the data stream shared by pure clones, not inode/source name identity, complete metadata equality or an immutable snapshot. Hard-link acquisition already retains the same inode, so clone-ID equality is auxiliary rather than its provenance proof. It may be useful for a later approved FD-based `fclonefileat` snapshot experiment, but such cloning has separate metadata/budget obligations and is not selected here.
- **`ATTR_CMN_FILEID`**: object identity within the mounted volume; combine with actual mount identity and retention. **`ATTR_CMNEXT_LINKID`** is link-specific on supporting filesystems and distinct from file ID, without an inferred numerical relation. It may strengthen entry tracking, but neither its value nor a receipt authorizes adoption or unlinking after an unknown interruption.
- **`ATTR_CMN_DOCUMENT_ID`** survives safe saves by design and is not exact-object identity. Kqueue change events are advisory invalidation aids, not an atomic no-change certificate. No token replaces complete metadata inventory, bounded tree census, path/ancestor checks, preservation or removal authorization. [A4, P4]

The safe decoder must respect 4-byte attribute packing and signed relative references, require the returned bits at each observation, and bound both fixed and variable fields. Errors/unsupported properties must become explicit incomplete inspection, not fallbacks to equal zeroes or ordinary live-path readable open.

## 7. Finite implementation/acceptance seam

The smallest useful platform division is inside retained inspection, preserving the common manifest/budget/hold/removal logic rather than rewriting the whole lifecycle:

| Seam responsibility | Inputs / output / invariant |
| --- | --- |
| `held_directory_child` | Held parent + validated component → held directory and binding/mount observation; directory-only/nofollow acquisition, no payload file open. |
| `bounded_directory_batch` | Fresh independently opened directory cursor + caller budget/storage → exact counted records or explicit error; no hidden growth/unbounded retry, no stale records. |
| `anchored_object_attributes` | Held parent + component, or already-safe FD + bounded requested set → returned-mask-bearing real identity/data/ACL observation; no data-open prerequisite. |
| `acquire_owned_capture_link` | Active protected same-mount stage + held source parent/name + reservation → one tracked entry or held uncertain outcome; never recursive capture/overwrite. |
| `open_validated_capture` | Proven active regular capture + fresh source/ancestor/stage checks → retained readable FD, or refusal before open. Safe handoff depends on established namespace exclusion. |
| `validate_and_finish_capture` | Retained observations + full data/metadata/census checks → inspection result; exact active-link cleanup only, preserving unknown outcomes and charge. |

These are design responsibilities, not proposed public API scaffolding or a production patch. **Already possible with the lock:** component validation, FD ownership, link/stat/open/statfs operations and byte-based parsers. **Missing safe native surface:** attribute calls, raw counted bulk batches, and access/topology observations if not satisfied through an approved existing library. One narrow Darwin observation binding can cover those without exposing raw pointers to Work. [R1–R9]

Only the following finite evidence packet is needed to move this candidate to HITL acceptance review; none was executed by this lane:

1. **Binding/decoder review:** chosen approved version compiles under the intended targets without Work unsafe; source-level malformed/truncated/overflow/reference/mask/count/stale-buffer tests fail closed; explicit EOF/fresh-cursor/error/refill/retry budget tests. No need to rerun unstructured stress tests as a substitute for this contract.
2. **Stage and ordinary concurrency schedules:** inherited benign and dangerous ACL grants; protected parent replacement/deletion; source writable FD/mmap, rename/replacement/ancestor move, concurrent user-link changes, own ctime transitions; verify **zero payload-readable opens** on every pre-read refusal schedule. Prove both unrelated-principal stage exclusion and active-Work actor exclusion.
3. **One bounded topology packet:** native source/stage same/different-mount link behavior, real-vs-logical volume identity, mountpoint/firmlink bulk-versus-open observations, nested mount/topology change refusal and case/alias binding on intended OS/APFS variants. State whether prevention-before-crossing or validated observed containment has actually been established. Do not substitute APFS name/type checks.
4. **Interruption packet:** success-before-result-record, result-before-validation, active cleanup failure and unidentified leftover; demonstrate owned-entry evidence, holds and retained resources without automatic unknown cleanup. Qualification on macOS 15/26 remains separate from the existing 27.0.1 toy evidence.

**Decision-ready disposition:** hard-link acquisition removes the specific recursive-clone budget blocker and offers a defensible pre-readable-open handoff under the approved cooperative threat boundary **if stage namespace exclusion is demonstrated**. Current locked bindings do not yet expose all required safe observations. Source consistency during own metadata mutation, complete bounded native enumeration, and strict no-XDEV equivalence remain bounded acceptance obligations. The handoff should carry these exact blockers and the conditional seam, not “macOS impossible,” “rustix lacks it so Darwin lacks it,” a blanket storage ban, or accepted full support. #23/#20 remain with the parent/operator for acceptance and sequencing; no status/map changes are made here.
