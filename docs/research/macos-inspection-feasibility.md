# Public macOS inspection protocols: bounded feasibility review

## Answer and scope

**No complete public, unprivileged protocol satisfying the entire retained-object inspection boundary is established by this pass. This is a narrowly stated proof/capability gap, not a finding that macOS support is impossible.** A public clone-first protocol can separate acquisition from readable opening and data consumption. In particular, **capture → validate → readable-open/read** was not implemented by the previous probes and must not be rejected on the ground that they deliberately read their captures immediately.

There are stronger public observations than their inode/timestamp checks: `ATTR_CMN_GEN_COUNT` documents data-change detection, and `ATTR_CMNEXT_CLONEID` documents shared data-stream identity. These make a staged, validated data-view candidate materially more defensible than clone-plus-stat alone. Neither documents retention of the original live vnode, an atomic identity-qualified clone, an atomic source-to-destination metadata receipt, or exclusion of active same-UID writers. The source-to-stage and stage-to-readable-handle handoffs, directory substitution and complete live-tree/metadata consistency remain specific obligations. [A4–A7]

This answers the factual question in [Assess public macOS inspection protocols against the exact safety boundary](https://github.com/techwright-lab/work-cli/issues/25). It does **not** accept a design or resolve [Demonstrate safe retained-object inspection on macOS](https://github.com/techwright-lab/work-cli/issues/23), change the [map](https://github.com/techwright-lab/work-cli/issues/13), authorize production staging, choose a threat-model relaxation, or establish release readiness.

## 1. Contract versus one Linux mechanism

The approved [core safety resolution][W1] requires complete safe core support, refusal/holds on replaced paths, special files, forbidden mount crossings and uncertainty, and separate explicit stopped-writer authorization for actual removal. The [storage refinement][W2] requires operation-specific evidence and preservation of unknown metadata; it does not authorize blanket ACL rejection or universal cloud detection. The prototype question additionally calls for retained exact-object inspection and rejection of special files before readable open. **This review treats those as requirements, not expendable implementation details.**

The baseline implements them using `O_PATH` acquisition with `openat2` resolution restrictions, retained descriptors and identity records, type/link-count validation, trusted `/proc/<pid>/fd` reopening, then name/ancestor/identity rechecks before bytes are read. Directory enumeration uses a fresh readable open of `.` with directory restriction, not a duplicated exhausted cursor. The identity record includes device/inode/mode/links/owner/size/mtime/ctime, not merely inode. [W3]

The regression [`descriptor_reopen_never_opens_a_replacement`][W3T] replaces a pathname immediately before the data open. It asserts the opened inode is the retained original, the result is `Changed`, and observed file bytes are zero. This is strong evidence of the intended original-object data boundary. However:

1. The original-inode assertion is specific to a retained-original implementation. A correctly authenticated clone is necessarily a new inode; different inode alone does not prove unsafe bytes or policy failure. A staged equivalent needs an explicit equivalence argument and corresponding regression, not a false original-inode assertion.
2. Zero bytes in that schedule follows from rechecking before read. It does **not** prove every changed input is detected before any bytes, nor require that capture itself be a readable open. Linux also reads mutable file contents with before/after checks; this is not a documented atomic snapshot of every live file or metadata item under every hostile write schedule.
3. Conversely, merely returning `Changed` after opening a replacement FIFO/device does not preserve type-before-readable-open. `O_NONBLOCK` only avoids some blocking; it is not a regular-file filter or protection against device-open effects.

Thus neither “must use Linux syscalls” nor “eventually notices a mismatch, so equivalent” is justified. A clone architecture must say whether it proves original-object provenance, equal data streams, or only a stable-tree assumption, and which boundary each proof precedes.

## 2. Candidate screen: handles and reopening

| Candidate and order | What primary sources support | Exact gap/refusal |
| --- | --- | --- |
| No-follow `fstatat`/`getattrlistat` → validate → ordinary readable `openat` | Metadata lookup without opening a data descriptor; current `getattrlistat` source propagates no-follow/beneath options. [A1, A7] | Observation is not retention. Swap regular file for FIFO/device between check and open. Post-open `fstat` is too late for the initial open boundary. Refuse rather than fall back to this sequence. |
| `O_EVTONLY` → `fstat` → `dup` or `/dev/fd/N` | Event monitoring descriptor; source conditionally strips read/write only if process policy requests it, and proceeds through vnode open. Prototype read through event-only succeeded; FIFO acquisition succeeded. [A1–A3, W4] | Not a universal metadata-only, type-filtered acquisition. Even if read access were disabled, no established bypass of special-file open effects. Duplication cannot undo an unsafe first acquisition. |
| `O_EXEC` → validate → read transition | Access-mode bits remove read/write; existing-object authorization rejects nonregular files and requires execute authorization for regular files. [A1, A2] | Ordinary 0600 non-executable data is legitimate payload but fails. No chmod/permission-repair or execute-only payload policy is authorized. This is not a general file-inspection strategy. |
| `O_SEARCH`/`O_DIRECTORY` for directories → new `openat(fd, ".", O_RDONLY|O_DIRECTORY|...)` | Directory restriction/search authorization is a useful distinct capability. `O_DIRECTORY` is documented to reject nondirectories. [A1, A2] | Do not confuse the regular-file gap with a total absence of directory handles. Native version, compound-open ordering, ancestor and mount evidence still need qualification. A fresh open, not `dup`, is needed for independent cursors. |
| Valid retained descriptor → `/dev/fd/N` or `dup` | Apple's fdesc implementation requests descriptor duplication; `open1` handles that request. This explains the prototype's retained inode and shared offset. [A3, W4] | No general conversion from nonreadable arbitrary metadata handle to readable original object is established. Access mode cannot simply be upgraded by duplication. Trust in `/dev/fd`, FD lifetime/reuse, and cursor ownership require an explicit design; it does not solve first acquisition. |

Kqueue is a change **notification**, not an atomic acquisition barrier. Its manual describes aggregation and vnode events attached to an already acquired FD. A notification can conservatively invalidate a capture; no cited guarantee makes “no event observed yet” an authenticated, complete no-change certificate covering the whole capture/validation interval. [A9] Neither notifications nor extra polling repair the initial unsafe-open race.

## 3. File identity, authenticated open and filehandles

- **File IDs and paths:** `ATTR_CMN_FILEID` identifies the object within its mounted volume and corresponds to `st_ino`. Persistent IDs survive mount/unmount on supporting filesystems; document IDs deliberately survive safe saves, so document ID is not exact-object identity. `fsgetpath` reconstructs a pathname (one possible path for hardlinks); it neither returns a retained descriptor nor makes the later open atomic with reconstruction. Sequence ID → path → ordinary open retains the replacement race. [A7, A8]
- **`openbyid_np`:** the inspected implementation explicitly requires an Apple platform binary or `com.apple.private.vfs.open-by-id`. It reconstructs a path and supplies expected IDs to an internal open. That is not an eligible unprivileged third-party CLI solution; it was not invoked. [A4]
- **Correction to the earlier checkpoint's stronger ordering language:** the internal `VA_VAFILEID` check is before ordinary `VNOP_OPEN` on the noncompound route. But the same source has a possible `VNOP_COMPOUND_OPEN` earlier. Therefore this source does not establish “expected ID is always checked before any filesystem open.” Ordinary public `openat` also passes null expected IDs. Do not promote a private primitive or a partial code path into a public contract. [A2, A4]
- **`openat_authenticated_np`:** public header declaration is not evidence of file-ID authentication. The libsyscall wrapper requests `O_DP_AUTHENTICATE`; `vn_open_auth` documents checking that the opened file is on the same authenticated **volume** as `authfd` on a supporting filesystem. Its noncompound path invokes `FSIOC_AUTH_FS`. It does not compare the two vnode identities as an expected-original-object condition. No private entitlement is needed to reject it on semantic grounds: volume authentication is the wrong proof. Exact runtime availability remains unqualified. [A1, A2, A5]
- **`getfh` → `fhopen`:** Apple's manuals restrict both to superuser/NFS uses. Not a public unprivileged acquisition/reopen protocol for Work. No elevation or filehandle operation was attempted. [A8]
- **`fclonefileat`:** identifies its source by FD, which would avoid a later source-name lookup, but still needs a safely acquired original FD. Starting with the rejected event-only/execute-only strategy does not cure that prerequisite. [A6]

**Narrow result:** the screened interfaces do not establish a general public “retain arbitrary object without special-file readable/open effects, validate, then read exactly that retained regular object” primitive. This is a result about these interfaces and the missing proof, not all possible macOS designs.

## 4. Clone-first: what changes, and what does not

### Proven source/API properties

`clonefileat(parent, name, stage_parent, new_name, flags)` resolves the source and performs clone acquisition without a source readable descriptor in the caller. In the inspected kernel, source types other than regular files, symlinks and eligible directories are rejected before `VNOP_CLONEFILE`; source read authorization is still required. Source and destination must have the same mounted filesystem, and an existing destination is refused. The API returns status, **not** a source identity receipt or destination FD. [A4, A6]

The manual says the clone shares data blocks, has its own attributes/xattrs with explicit ownership/mode/ACL exceptions, and subsequent writes are private (copy-on-write). Its “atomic” language describes all-new-objects-or-none creation, not an atomic snapshot of the entire concurrently changing source tree. A successful clone is not a metadata-preservation receipt: owner may differ, setuid/setgid bits are cleared, and ACL inheritance/copy has explicit rules. [A6]

The absence of an ordinary source `VNOP_OPEN` in this wrapper is useful evidence for avoiding the FIFO/device readable-open problem, not proof that capture is semantically free of reading: clone requires data-read authorization, captures data, allocates metadata and may involve filesystem/provider work. Whether “passive preview” permits bounded temporary capture is a separate design/acceptance obligation, not permission supplied by this review.

**Important type/resource hole:** clone acquisition admits directories too. There is no regular-only or expected-source-ID flag in the inspected public clone header. A regular-file precheck followed by substitution with a directory is not atomically excluded. The manual discourages hierarchy cloning. Do not claim a bounded per-file capture from a prechecked size alone: directory substitution, growth, copied xattrs and time spent inside a syscall need their own bound/refusal argument. [A4, A6]

### Evidence stronger than timestamp equality

1. **`ATTR_CMN_GEN_COUNT`:** Apple's manual says a nonzero monotonic count tracks data modifications; unchanged count for the same object indicates identical data. Zero is invalid, including while mmap'ed. It requires `FSOPT_ATTR_CMN_EXTENDED`. This is stronger documented data-change evidence than ctime uniqueness. The attribute is not a namespace, ACL/xattr or whole-tree generation certificate. Endpoint nonzero observations alone are not a proved exclusion of an intervening writable-mmap interval, wrap/reuse, or object substitution. [A7]
2. **`ATTR_CMNEXT_CLONEID`:** documented as identifying the data stream, shared by pure clones; kernel `vnode_attr` describes a unique ID shared by “perfect” clones. This can be tested as a source-stream/stage-stream association before reading. It is **not source inode identity**, nor documented here as equality of every ACL/xattr/fork or proof that the live name never changed. Support/validity/stability on each admitted OS/filesystem and behavior as a first clone is created remain obligations. [A7]
3. **Returned attributes matter:** VFS can pack zero for unsupported clone-ID/generation fields. Require returned-attribute masks and valid values, not a successful syscall with two equal zeroes. The mappings request read-attributes permission, not a private entitlement, but public availability does not guarantee support on every volume. [A7]

Neither new field was used in experiment 4. The report cannot conclude these mechanisms fail merely because inode-only checks failed there. Nor does finding these fields complete a proof of original-vnode retention.

### Concrete conditional protocol and order of operations

The following is a **candidate**, not accepted production design. Its straightforward correctness argument is conditional on an unchanged/cooperating source namespace and protected staging during the full interval. Under active writers, the obligations below must be discharged rather than assumed.

1. **Establish operation context and budgets.** Retain/revalidate root and ancestor directory bindings and the registered checkout identity. Resolve one-component names relative to held parents, reject symlinks/escapes, and establish permitted mount/real-volume identity. Keep explicit limits for names, depth, entries, FDs, calls, time, staged objects, logical bytes and metadata; charge capture work, not only later reads. Create an owned, separately accounted, same-volume stage only if that operation is authorized to do so. Do not stage inside the source census and thereby invalidate it.
2. **Metadata census before capture.** Bounded fresh directory enumeration; collect source type, volume/file ID, link count, ownership/mode, sizes/times/flags, relevant ACL/xattr/fork inventory, returned-field masks, data generation and stream ID where supported. Reject nonregular/non-directory objects and multiply linked regular files under the existing baseline rule. For files, retain the pre-capture source record `S0` separately from any clone identity. No readable payload open yet.
3. **Capture without consumption.** For each admitted regular path, call `clonefileat` into a fresh stage name, with supported `CLONE_NOFOLLOW_ANY`/`CLONE_NOFOLLOW` and beneath restriction where available. No source-path readable fallback, recursive-copy fallback, overwrite, or repair. **Do not open/read the clone yet.** On ambiguous outcome retain evidence/accounting and refuse destructive progress.
4. **Validate before readable open.** Re-enumerate/revalidate the live bindings and collect `S1`. Require accepted source identity and metadata equality, supported nonzero unchanged source data generation, and a supported valid stage stream ID matching the source stream observations under the qualified token rules. Check stage type is regular, stage link count/size/budget, stage metadata and fresh name binding. Do not equate stage inode/owner with the source record. Reject on any mismatch or unsupported proof. If tokens change on first clone creation, or an attribute is unavailable, this candidate refuses rather than inventing a timestamp fallback.
5. **Readable transition, then bounded consumption.** Only after step 4, obtain a readable handle to the validated staged regular object; check the returned FD identity before reading and retain it. This step **still needs a race-safe handoff proof** if another admitted writer can alter the stage. Hash/read only bounded staged bytes, reserve EOF/growth work, check FD identity/size/generation before/after, and never read the live source pathname. Revalidate live source/tree evidence after reading and before any destructive use; a late mismatch yields incomplete inspection/hold, not an accepted result. Do not promise zero already-read bytes for changes that occur after the pre-read barrier.
6. **No deletion authority from capture.** Preview, stopped-writer confirmation, preservation, fresh removal checks, durable outcome and charge reconciliation remain separate. Stage lifetime, failure/crash recovery and unknown cleanup outcomes must not destroy source/evidence or silently release charge. No new backup system is authorized.

**Why this ordering matters:** replay the two experiment-4 schedules, but compare the fuller stamps before step 5. Both deliberately time-separated changes would be rejected with **no clone data read or readable clone open**. That follows from the reported comparisons and the revised control flow; it is not a newly executed test. Under true source/stage quiescence the clone captures the stable regular file, and COW separates later writes. This is a coherent conditional argument, unlike mandatory read-then-reject. It is not yet the original-vnode argument.

### Counterexamples and unresolved obligations

| Situation | What remains to prove or refuse |
| --- | --- |
| Source A is moved away, B cloned, A restored | Inode equality alone accepts B, as observed. Unchanged timestamps are not a documented complete anti-ABA certificate. A different valid stream ID can reject different data, but matching clone IDs proves stream equivalence, not that A was the vnode cloned. Same-stream B is still B for a literal original-object requirement. |
| Contents are overwritten/restored | Experiment 4 defeated inode/size/mtime. Nonzero generation is a better documented data witness, but complete mmap/wrap/reuse semantics over the interval and qualification remain open. Clones are not proof of unmodified live metadata. |
| Stage entry replaced after validation, before readable open | `openat(..., O_RDONLY|O_NOFOLLOW)` can open a substituted FIFO/device before post-open type checking. 0700 protects against other principals subject to access checks, **not arbitrary processes with the same UID**. A destination FD retained atomically at creation or another proved exclusion mechanism is missing from this candidate. Do not label this race solved by a private directory. |
| Source regular path becomes directory during capture | Clone's accepted type set includes directories; no regular-only flag was found. Prechecks and postchecks do not establish a hard capture budget under this race. |
| Ancestor moved outside root; nested mount encountered | Beneath is relative to the supplied FD, not eternal membership of the original root. Same-filesystem destination check is useful, but is not universal no-mount-traversal proof. Post-observed device equality alone is not `NO_XDEV`. Retain/revalidate ancestors and prove the exact permitted topology/OS behavior; otherwise refuse. [W4, A1, A4] |
| ACL/xattr/resource fork changes or clone exceptions | Stat, data generation and main-stream identity do not document complete metadata equality. Keep original metadata evidence; unknown/unpreserved payload holds removal. Attribute enumeration/read races and bounds need their own protocol. [W2, A6, A7] |
| Different files captured at different times | Per-file clone atomicity does not supply a coherent whole-tree/registration/common-Git manifest. Repeated bounded censuses and input binding are necessary, not proof against every restored intermediate state. |

## 5. Stopped-writer authority is not a technical exclusion mechanism

Under **actual quiescence/cooperation** throughout census, capture, validation, read and destructive use, the conditional candidate has a simple provenance argument: the anchored source name cannot be rebound and its bytes/metadata cannot change; the clone is acquired from that source and read only after validation. An operator statement can be a required authorization, but is not an OS-enforced guarantee that those assumptions hold. Acquiring Work's own lock does not exclude unrelated tools; Apple describes ordinary record locking as advisory. [W1, A10]

Under **active or malicious same-UID filesystem writers**, do not assume stage privacy or no source mutations. Retained original-object Linux reopening does protect a particular readable-open boundary even during replacement; its subsequent metadata checks do not establish a magical globally immutable filesystem. A macOS substitute must preserve that boundary or explicitly demonstrate an equivalent safety property. Conversely, it would overstate baseline guarantees to demand proof against arbitrary process compromise or every undetectable content mutation while claiming Linux already proves that.

**Unresolved boundary, not research policy:** which technical race guarantees must hold even when a stopped-writer declaration is mistaken, and whether authenticated staged data-stream equivalence can implement the approved retained-object requirement without literal original-vnode identity. The existing approvals cannot be silently read as permission to rely only on cooperation. Any proposed reduction of protection is a human decision; none is selected here.

## 6. Version, bindings and exact refusal boundary

The older `xnu-11215.1.10` public headers already contain `O_NOFOLLOW_ANY`, `O_EXEC`/`O_SEARCH`, clone calls/`CLONE_NOFOLLOW_ANY`, generation and clone-ID documentation. They do **not** contain the newer `O_RESOLVE_BENEATH`/`CLONE_RESOLVE_BENEATH` definitions present at `xnu-12377.1.9`. Clone entry points themselves are annotated available from macOS 10.12; that does not date every newer flag. No macOS 15 fallback may simply pass an unqualified numeric flag or assert beneath behavior from the macOS 27 toy run. Single-component held-parent traversal is a possible separate strategy, not a demonstrated replacement for all beneath/mount guarantees. [A1, A6, A7, A11]

`getdirentries` provides bounded buffer transfer and advances an FD cursor. A complete collector still needs validated record parsing, per-entry/refill/deadline budgets, repeated complete enumeration, and fresh cursor opens. No safe Rust wrapper/ownership/error-mapping implementation or supported-version native qualification was established here. [A9, W3]

For this candidate, **refuse before payload readable-open/read** on unresolved source/stage binding, disallowed type/link count/path/mount, unavailable/invalid returned token, any required mismatch, insufficient metadata proof, unsupported flag/capability, or exhausted capture/inspection budget. **After read**, a fresh mismatch or error invalidates the result and holds removal; do not pretend earlier data consumption did not happen. Capture itself must also be refused where boundedness or safe source-type behavior cannot be established. There is no fallback to ordinary source readable-open, Git cleanliness, stripped metadata, inferred stopped writers, or forgotten stage accounting.

## 7. Disposition and next HITL decision

The bounded factual result is sufficient to resolve this research ticket with explicit unknowns:

- Event/execute/descriptor-reopen and ID/filehandle/authentication candidates do not establish an eligible complete original-object protocol for ordinary payload.
- Clone-first is **not refuted by the prior probes' immediate reads**. Generation/stream IDs plus validation-before-readable-open/read support a concrete conditional staged-data candidate.
- **Still missing:** a public, safe-Rust-accessible proof/protocol for source-object (or accepted equivalent stream) provenance, safe bounded capture despite type/namespace changes, race-safe stage-to-readable-FD handoff, and complete metadata/tree/mount consistency on supported versions. No complete equivalent is claimed; no universal impossibility is claimed.

The exact next HITL item belongs to the still-open prototype parent: **review this conditional candidate and its explicit threat boundary, and decide whether to authorize a bounded design/qualification follow-up under the unchanged contract.** That follow-up must first resolve the source/stage handoff and bounded-type obligations; more timestamp stress tests alone are not the answer. If it would rely solely on cooperative quiescence or replace exact-original-object protection with a weaker property, obtain an explicit decision about that precise difference **before** implementation. This report neither selects that policy nor authorizes another native experiment. Support remains blocked until equivalence is demonstrated and accepted.
